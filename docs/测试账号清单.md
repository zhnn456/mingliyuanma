## 六、数据隔离机制

### 隔离规则

| 当前登录账号 | 可见用户范围 | 可见管理员范围 |
|--------------|-------------|----------------|
| 主管理员（282063152@qq.com） | 全部用户 | 全部管理员 |
| 测试管理员（admin@test.com 等） | 测试用户（邮箱含 test/demo/example） | 测试管理员（邮箱含 test） |
| 演示账号（demo@ming8.online） | 测试用户 | 测试管理员 |
| 代理商（agent 角色） | 仅自己的客户 | 无管理员列表权限 |

### 实现方式

- **隔离模块**：`src/lib/test-isolation.ts`
  - `PRIMARY_ADMIN_IDS = ['admin', 'cm1admin001']` — 主管理员 ID 白名单
  - `PRIMARY_ADMIN_EMAILS = ['282063152@qq.com']` — 主管理员邮箱白名单
  - `isPrimaryAdmin(session)` — 判断当前登录者是否为主管理员
  - `buildUserIsolationClause(session)` — 构造用户列表过滤条件
  - `buildAdminIsolationClause(session)` — 构造管理员列表过滤条件

- **应用层**：
  - `src/app/api/admin/users/route.ts` — 用户列表 API 加隔离
  - `src/app/api/admin/admins/route.ts` — 管理员列表 API 加隔离

### 安全保障

1. 测试账号无法看到主管理员的邮箱和用户ID，无法通过测试账号猜测或获取最高权限
2. 测试账号无法看到真实用户数据，保护用户隐私
3. 演示账号额外锁定写操作，防止误操作或恶意修改测试数据
4. 隔离逻辑在后端 API 层实现，前端绕过无效
