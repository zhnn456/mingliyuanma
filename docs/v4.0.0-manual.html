一、系统概述与架构

1.1 系统架构

命理网 v4.0.0 采用 单实例多租户 的 SaaS 架构，由中央管理系统和多个独立代理商实例组成：

架构特点：
  • 中央管理系统统一管理代理商、授权码、版本发布
  • 每个代理商拥有独立的 Cloudflare Worker 实例
  • 每个代理商拥有独立的 D1 数据库，数据天然隔离
  • 所有支付必须通过中央结算，防止代理商截留资金
  • 代理商通过授权码验证身份，无授权码无法运行

2.3 版本管理操作

入口：侧边栏 → 系统 → 版本管理

发布新版本步骤：

  1. 点击右上角「发布新版本」按钮
  2. 填写版本号（格式：vX.Y.Z，如 v4.1.0）
  3. 填写版本标题（简短描述本次更新）
  4. 填写源码下载地址和校验码（可选）
  5. 分类填写更新内容：
    • 新增功能：添加新功能列表
    • 改进优化：列出优化改进项
    • 问题修复：列出修复的 Bug
  6. 勾选「设为最新版本」（代理商将收到更新推送）
  7. 点击「确认发布」完成

版本操作按钮说明：

按钮功能使用场景
设为最新将版本标记为最新，所有代理商可见发布后纠正版本顺序
弃用标记版本为已弃用发现版本有严重问题时
恢复恢复已弃用的版本弃用后需要重新启用
删除永久删除版本记录清理测试版本（谨慎操作）

三、代理商后台操作指南

3.1 代理商后台入口

代理商使用分配的账号密码登录，自动进入代理商后台。

3.2 侧边栏菜单

菜单图标权限说明
数据概览📊只读今日/本月统计数据
收益看板💰只读销售额趋势、转化率图表
我的订单🧾只读本代理商所有订单
分润明细📈只读每笔订单的分润记录
结算中心🏦申请申请结算、查看结算记录
客户管理👥只读本代理商用户列表
代理设置⚙️可编辑品牌定制（Logo/名称/配色）
系统更新🔄只读检查更新、查看日志
⚠️ 代理商禁止操作：
  • ❌ 创建新代理商（防止发展下级）
  • ❌ 生成授权码（只有中央能生成）
  • ❌ 直接处理支付（必须走中央代理）
  • ❌ 修改分润比例（由中央制定）
  • ❌ 导出全部数据（防止数据泄露）

3.3 申请结算步骤

  1. 进入「结算中心」页面
  2. 查看当前待结算分润金额
  3. 点击「申请结算」按钮
  4. 系统自动提交结算申请到中央
  5. 等待管理员审核（通常 1-3 个工作日）
  6. 审核通过后，资金打入绑定的收款账户

四、授权码管理与生成

4.1 授权码格式

// 授权码结构：LIC.payload.signature // 示例： LIC.eyJhZ2VudElkIjoiYWdlbnRfMDAxIn0.a3f8k2m5... // 组成部分： LIC. // 固定前缀 ey... // Base64 编码的载荷 .a3f7k2m9 // HMAC-SHA256 签名

4.2 授权码包含信息

字段说明示例
agentId代理商唯一标识agent_001
features功能权限列表["bazi","ziwei","qimen"]
maxUsers最大用户数限制1000
expiryAt到期时间2025-12-31T23:59:59Z
level代理商等级basic/standard/premium
monthlyFee月费金额299

4.3 生成授权码步骤

  1. 进入管理后台 → 代理商 → 授权码管理
  2. 点击「创建授权码」
  3. 填写代理商信息：
    • 绑定域名（如 agent-001.mingli.workers.dev）
    • 功能权限（排盘类型、营销工具等）
    • 代理商等级（决定分润比例）
    • 最大用户数限制
    • 有效期（到期时间）
  4. 系统使用 HMAC-SHA256 生成签名授权码
  5. 保存授权码并交付给代理商
🔒 授权码安全提醒：
  • 授权码绑定域名，其他域名使用无效
  • 授权码包含签名，无法伪造
  • 过期授权码自动失效
  • 不要将授权码泄露给第三方

五、代理商部署流程

5.1 前置条件

  • 已注册 Cloudflare 账号
  • 已安装 Node.js v18+
  • 已获得平台交付的源码包和授权码

5.2 一键部署（推荐）

# 1. 解压源码包 unzip mingli-agent.zip cd mingli-agent # 2. 安装依赖 npm install # 3. 运行一键部署脚本 node scripts/deploy-agent.js

脚本会自动引导完成：

  1. 检查 Node.js 和 wrangler 环境
  2. 引导登录 Cloudflare
  3. 填写代理商代号、品牌名、授权码
  4. 自动创建 D1 数据库
  5. 自动创建 KV 命名空间
  6. 自动生成 wrangler.toml 配置
  7. 自动初始化数据库表
  8. 自动构建并部署到 Cloudflare Workers

5.3 手动部署

如果一键脚本失败，可手动执行以下步骤：

# 1. 登录 Cloudflare wrangler login # 2. 创建 D1 数据库 wrangler d1 create mingli-agent-{代理商代号} # 3. 创建 KV 命名空间 wrangler kv:namespace create KV # 4. 初始化数据库 wrangler d1 execute mingli-agent-{代号} --remote --file=prisma/migrate_v4.sql # 5. 构建项目 npm run build:worker # 6. 部署 npx wrangler deploy

六、版本更新流程

6.1 管理后台发布版本

步骤详见 第 2.3 节。

6.2 代理商检查更新

  1. 代理商系统每 30 分钟自动检查一次更新
  2. 如有新版本，代理商后台顶部显示更新提示
  3. 进入「系统更新」页面查看详情
  4. 点击「立即更新」按钮
  5. 系统自动下载新版本并完成部署

6.3 回滚版本

如果新版本出现问题，可以：

  1. 管理后台 → 版本管理 → 找到上一个稳定版本
  2. 点击「设为最新」将其恢复为最新版本
  3. 代理商下次检查更新时会自动回滚

八、安全机制说明

8.1 授权码安全

机制说明
HMAC 签名使用中央密钥签名，无法伪造
域名绑定授权码绑定具体域名，跨域名无效
时效验证过期自动失效
远程验证每次启动都向中央服务器验证

8.2 容错机制

场景处理方式
中央服务器宕机24 小时宽限期，正常运行
超过 24 小时功能降级，限制新订单
超过 72 小时只读模式，禁止新注册
授权过期限制所有运营功能

8.3 防篡改机制

机制说明
源码水印构建时注入 agentId + brandName
完整性校验检测关键文件是否被篡改
远程巡检中央定时请求代理商水印接口
支付强制代理无法绕过中央直接收款

九、常见问题排查

Q: 代理商系统无法启动，提示"授权验证失败"？

A: 检查以下几点：

  • APP_LICENSE_KEY 是否正确配置
  • CENTER_API 是否指向正确的中央服务器
  • 域名是否与授权码绑定的一致
  • 授权码是否已过期
Q: 代理商后台显示"离线模式"？

A: 说明无法连接中央服务器。可能原因：

  • 中央服务器正在维护
  • 网络问题导致无法访问
  • 在 24 小时宽限期内仍可使用，尽快联系管理员
Q: 如何获取最新版本更新？

A:

  1. 确保系统已连接中央服务器
  2. 进入「系统更新」页面
  3. 点击「立即更新」按钮
  4. 等待自动完成部署
Q: 忘记管理员密码怎么办？

A: 联系平台管理员重置密码。代理商无权重置管理员密码。
