## 3. 代理商管理

### 3.1 两种代理模式本质区别

| 维度 | SaaS代理（saas） | 源码部署代理（source） |
|------|-----------------|----------------------|
| **身份定位** | 主平台的销售渠道 | 独立运营商（平台客户） |
| **系统所有权** | 无系统，租用主平台 | 拥有一套完整系统 |
| **服务器** | 主平台服务器 | 代理商自己的服务器 |
| **数据库** | 主平台数据库（共享） | 代理独立数据库 |
| **支付通道** | 主平台的支付账户 | 代理商自己的支付账户 |
| **资金流向** | 客户→主平台→分润给代理 | 客户→代理账户（100%） |
| **客户归属** | 客户在主平台注册，归属于代理 | 客户完全属于代理，与主平台无关 |
| **后台位置** | 在主平台上的 `/agent` 后台 | 在代理自己服务器上的完整后台 |

### 3.2 创建代理商

**操作路径：** 管理后台 → 代理商管理 → 创建代理商

**步骤：**

1. 点击「+ 创建代理商」
2. 填写信息：
   - **登录邮箱**：代理商登录账号
   - **品牌名称**：代理商网站名称
   - **绑定域名**：代理商自有域名（源码部署必填）
   - **联系人 / 联系电话**
3. 选择代理类型：
   - SaaS 代理 → 选套餐（试用/月费/年费）
   - 源码部署代理 → 选授权（年度/永久）
4. 设置分润比例（SaaS 默认 30%，源码部署固定为 0）
5. 点击「创建」

**创建后系统自动执行：**
- 创建 User 账号（role=agent）+ Agent 记录
- 生成 HMAC-SHA256 签名授权码
- 生成邀请码（REF + 6位随机字符）
- 开通试用期（SaaS）或设置授权期限（源码）

**交付给代理商的信息模板：**
```

━━━━━━━━━━━━━━━━━━━━━━━━━

登录地址：https://ming8.online/login
登录邮箱：[代理商邮箱]
初始密码：[初始密码]

代理商后台：https://ming8.online/agent
授权码：[XXXX-XXXX-XXXX-XXXX]

请尽快修改密码并妥善保管授权码。
━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 4. 授权码管理

### 4.1 授权码原理

授权码使用 **HMAC-SHA256 签名**生成，包含以下信息：
- 代理商 ID
- 绑定域名
- 授权期限
- 功能权限
- 防篡改签名

**授权码格式：** `XXXX-XXXX-XXXX-XXXX`（16 位分段）

### 4.2 授权码操作

| 操作 | 说明 | 影响 |
|------|------|------|
| 查看授权码 | 查看所有授权码及状态 | 无 |
| 重新生成 | 为代理商重新生成授权码 | 旧码立即失效 |
| 冻结/解冻 | 冻结授权码 | 代理商功能锁定 |
| 续期 | 延长授权有效期 | 即时生效 |
| 设置域名 | 修改绑定域名 | 需代理商重新部署 |

### 4.3 授权码状态

| 状态 | 说明 | 代理商表现 |
|------|------|-----------|
| 正常 | 授权有效 | 所有功能正常 |
| 即将到期 | 到期前 7 天 | 显示续费提醒 |
| 已过期 | 超过有效期 | 核心功能锁定，现有数据保留 |
| 已冻结 | 管理员冻结 | 全站锁定，仅保留登录页 |
| 已吊销 | 永久吊销 | 不可恢复 |

## 5. 分润与结算审核

### 5.1 分润机制

**触发时机：** 用户支付成功时自动触发

**分润流程：**
```
用户支付成功
  → 查询用户 agentId
  → 查询代理商 commissionRate（默认 30%）
  → 计算分润 = 订单金额 × 分润比例
  → 更新 Order 表（commissionRate, commissionAmount）
  → 更新 Agent 表（totalCommission, pendingCommission）
  → 写入 CommissionRecord 记录
```

**分润计算：**
```
分润基数 = 订单实付金额 - 支付手续费(1%) - 优惠券抵扣金额
分润金额 = 分润基数 × 代理分润比例
```

### 5.2 结算审核流程

```
代理商申请提现
      ↓
管理员审核（管理后台 → 结算审核）
      ├─ 通过 → 标记已打款 → 线下转账
      └─ 拒绝 → 退回代理商余额
```

### 5.3 提现规则

| 规则 | 标准 |
|------|------|
| 最低提现 | 100 元 |
| 每月次数 | 最多 3 次 |
| 手续费 | 5% |
| 审核时限 | 1-3 个工作日 |
| 打款方式 | 微信/支付宝/银行转账 |

## 7. 代码保护机制

### 7.1 七层保护体系

| 层 | 机制 | 说明 |
|---|------|------|
| 1 | 服务端逻辑保护 | 核心算法在 API 路由中，前端无法获取 |
| 2 | 前端代码混淆 | webpack-obfuscator，变量名十六进制化，字符串 base64 加密 |
| 3 | 域名绑定 | middleware.ts 校验，换域名返回 403 |
| 4 | 在线验证 | 10 分钟向主站验证授权状态 |
| 5 | 授权过期锁定 | 过期后全站锁定，仅保留登录页 |
| 6 | HMAC 签名 | 授权码加密生成，无法伪造 |
| 7 | 编译保护 | 部署后是编译产物，非原始源码 |

### 7.2 前端混淆配置

**文件：** `next.config.js`

| 混淆选项 | 说明 |
|----------|------|
| 字符串数组旋转 | 字符串打散重组 |
| 字符串加密 | 50% 字符串 base64 加密 |
| 变量名替换 | 变量名改为 `_0x3a2b` 十六进制格式 |
| 压缩输出 | 移除空格和换行 |

**排除项：** 第三方库（vendors、polyfills、manifest）不混淆。

### 7.3 域名绑定验证

**配置方式：** `.env.production` 环境变量

```toml
[vars]
APP_BOUND_DOMAIN = "agent.example.com"
APP_LICENSE_KEY = "xxxx-xxxx-xxxx-xxxx"
APP_AGENT_ID = "agt_xxx"
```

### 7.4 在线验证机制

| 参数 | 值 |
|------|-----|
| 验证间隔 | 10 分钟 |
| 失败锁定阈值 | 3 次 |
| 网络异常容忍 | 5 次 |
| 验证 API | `/api/license/verify` |
| 状态查询 | `/api/license/status` |

## 9. 系统维护与更新

### 9.1 版本发布 / 更新公告 / 系统更新日志

> 后台有三个名字相近的功能，职责完全不同，请勿混淆：

#### ① 版本发布（/admin/versions）
- **数据表**：Version 表
- **作用**：管理升级包（版本号、标题、下载链接、校验码），用于给代理商系统发版升级
- **消费者**：代理商客户端（通过 /api/version/check 检测更新）

#### ② 更新公告（/admin/updates）
- **数据表**：UpdateLog 表（kind = manual）
- **作用**：手动编写产品更新公告，展示给代理商和用户
- **消费者**：代理商端（通过 /api/agent/updates 拉取展示）

#### ③ 系统更新日志（/admin/update-logs）
- **数据表**：UpdateLog 表（kind = deploy / rollback）
- **作用**：自动记录每次部署和回滚操作，用于审计
- **消费者**：仅站长

```
版本发布     = 发"升级包"（给代理商系统更新用）      → Version 表
更新公告     = 写"更新说明"（给代理商/用户看）       → UpdateLog(kind=manual)
系统更新日志 = 记"部署流水"（给站长自己查）          → UpdateLog(kind=deploy/rollback)
```

### 9.2 部署流程

## 10. Z-Pay 支付配置

### 10.1 注册与获取凭证

1. 访问 https://z-pay.cn 注册商户账号
2. 登录后进入「商户中心」→「接口信息」获取：
   - **PID**：商户唯一标识
   - **KEY**：商户密钥（通信密钥）

> ⚠️ KEY 是敏感信息，务必妥善保管，不要提交到 Git 仓库

### 10.2 配置回调地址

| 配置项 | 填写内容 |
|--------|---------|
| 异步通知地址 | `https://ming8.online/api/payment/zpay/notify` |
| 同步跳转地址 | `https://ming8.online/payment/result` |

### 10.3 签名算法

```
1. 将参数按参数名 ASCII码从小到大排序（a-z）
2. sign、sign_type 和空值不参与签名
3. 拼接成 key=value&key=value 格式（参数值不编码）
4. 末尾追加商户 KEY，做 MD5 加密，结果为小写

sign = md5( 排序后的参数字符串 + KEY )
```

### 10.4 API 接口

**创建订单（API接口支付）：**
```
POST https://zpayz.cn/mapi.php
参数：pid, type, name, money, out_trade_no, notify_url, return_url, clientip, sign, sign_type
```

**返回示例：**
```json
{
  "code": 1,
  "msg": "success",
  "trade_no": "20160806151343349",
  "payurl": "https://xxx.cn/pay/wxpay/202010903/",
  "qrcode": "https://xxx.cn/pay/wxpay/202010903/"
}
```

## 11. 安全规范

### 11.1 防止代理商违规

| 风险 | 防护措施 |
|------|----------|
| 私自伪造授权码 | HMAC-SHA256 加密签名，无法伪造 |
| 换域名部署 | 域名绑定验证，不匹配返回 403 |
| 掐断与平台联系 | 在线验证，10 分钟无响应锁定 |
| 修改授权验证逻辑 | 核心逻辑在服务端，前端混淆无法逆向 |
| 二次倒卖源码 | 部署后是编译产物，非源码 |
| 授权过期继续使用 | 过期后全站锁定 |

### 11.2 违约处理

| 违规行为 | 处理方式 |
|----------|----------|
| 私自伪造授权码 | 立即吊销授权，不予退费 |
| 二次倒卖源码 | 立即吊销授权，追究法律责任 |
| 涉及违法宣传 | 冻结授权，整改后恢复 |
| 私自乱收费 | 冻结授权，退还违规收入 |
| 未按时续费 | 功能锁定，续费后恢复 |

### 11.3 管理员安全须知

- 管理员密码必须包含大小写字母+数字+特殊字符
- 定期修改密码（建议 30 天）
- 不在公共网络登录管理后台
- 操作敏感功能前确认环境正确
- 删除代理商前必须备份相关数据

## 12. 常见问题

### Q1：代理商测试账号在哪里创建？

管理后台 → 代理商管理 → 创建代理商，或通过 `/register-agent` 页面自助注册。测试完成后可在后台删除。

### Q2：授权码无法生成？

检查 AgentLicense 表是否有 `signature` 列。本地开发需执行 `node scripts/fix-local-db.cjs` 修复数据库。

### Q3：分润金额为 0？

检查：① 用户是否绑定了 agentId ② 代理商是否 active ③ CommissionRecord 表是否有 `productType` 列。

### Q4：代理商后台显示数据为空？

检查 `o.productType` 查询是否改为 `o.type`。Order 表的字段名是 `type` 不是 `productType`。

### Q5：BigInt 序列化报错？

Prisma raw query 返回 BigInt 类型，在 API 返回前加 `Number()` 转换。

### Q6：如何查看线上数据库数据？

```bash
mysql -u ming8 -p ming8_db -e "SELECT * FROM Agent LIMIT 5"
```

### Q7：部署后网站打不开？

1. 检查 `.env.production` 配置是否正确
2. 检查 MySQL 数据库连接
3. 检查环境变量是否完整
4. 查看服务器日志：`pm2 logs ming8 --lines 50`

### Q8：代码混淆是否生效？

GitHub 上的源码始终是明文（正常现象）。混淆在 `npm run build` 时生效，混淆后的产物在 `.next/` 目录（被 `.gitignore` 排除），部署到服务器后用户浏览器访问的是混淆后的代码。
