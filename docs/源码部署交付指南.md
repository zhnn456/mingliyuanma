## 三、部署步骤（详细）

### 第 1 步：上传源码包

```bash
# 方式一：通过 scp 上传
scp mingliyuanma-source-v4.0.0.zip root@你的服务器IP:/www/

# 方式二：通过宝塔面板上传
# 在宝塔面板「文件」中上传到 /www/ 目录
```

### 第 2 步：解压并安装依赖

```bash
cd /www
unzip mingliyuanma-source-v4.0.0.zip -d mingliyuanma
cd mingliyuanma
npm install
```

### 第 3 步：创建数据库

```bash
# 登录 MySQL
mysql -u root -p

# 在 MySQL 中执行：
CREATE DATABASE mingli_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'mingli'@'localhost' IDENTIFIED BY '你的数据库密码';
GRANT ALL PRIVILEGES ON mingli_db.* TO 'mingli'@'localhost';
FLUSH PRIVILEGES;
EXIT;

# 导入初始表结构
mysql -u mingli -p mingli_db < scripts/mysql-init.sql
```

### 第 4 步：配置环境变量

```bash
cp .env.example .env
```

编辑 `.env` 文件，填写以下关键配置：

```bash
# ===== 数据库配置 =====
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=mingli
MYSQL_PASSWORD=你设置的数据库名密码
MYSQL_DATABASE=mingli_db

# ===== 站点配置 =====
NEXTAUTH_URL=https://你的域名.com
NEXTAUTH_SECRET=（执行 openssl rand -hex 32 生成）

# ===== 授权配置 =====
APP_LICENSE_KEY=交付给你的授权码
CENTER_API=https://ming8.online

# ===== 站点信息 =====
SITE_NAME=你的品牌名称
AGENT_ID=交付给你的代理商ID

# ===== 服务器端口 =====
PORT=3001
```

### 第 5 步：构建项目

```bash
npm run build
```

构建成功后会生成 `.next/standalone/` 目录，这是独立运行版本。

### 第 6 步：启动服务

```bash
# 复制静态资源到 standalone
cp -r public .next/standalone/public
cp -r .next/static .next/standalone/.next/static

# 用 PM2 启动
pm2 start deploy/ecosystem.config.js
pm2 save
pm2 startup  # 设置开机自启
```

### 第 7 步：配置 Nginx

编辑 Nginx 配置文件（参考 `deploy/nginx.conf`）：

```nginx
server {
    listen 80;
    server_name 你的域名.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /_next/static/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_cache_valid 200 365d;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    client_max_body_size 50M;
}
```

### 第 8 步：配置 SSL 证书（推荐）

```bash
# 使用 Let's Encrypt 免费证书
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名.com
```

### 第 9 步：验证部署

```bash
# 检查服务状态
pm2 status

# 检查网站
curl -I http://localhost:3001

# 浏览器访问
https://你的域名.com
```

## 四、授权码激活

### 授权码说明

您的授权码格式为：`LIC.eyJhZ2VudElkIjoi...签名`

授权码中包含以下信息：
- 绑定域名（只能在此域名运行）
- 功能模块列表
- 最大用户数
- 授权等级（`source` = 源码买断）
- 过期时间（源码买断 = 永久）

### 配置方法

在 `.env` 文件中设置：

```bash
APP_LICENSE_KEY=LIC.你的完整授权码
CENTER_API=https://ming8.online
```

### 验证机制

系统启动后每隔 24 小时自动向中央服务器验证授权状态：

- **验证成功**：正常运行
- **网络中断**：24 小时内正常使用（宽限期）
- **超过 72 小时无法连接**：进入只读降级模式
- **授权码无效**：无法访问核心功能


`update.sh` 脚本会自动完成以下操作：

```
1. 备份当前版本（自动创建 backup-yyyyMMdd 目录）
2. 解压新版本代码包
3. 保留原有 .env 配置和数据库
4. 安装新依赖（如有）
5. 执行数据库迁移脚本（如有）
6. 重新构建项目
7. 重启 PM2 服务
8. 验证服务状态
```

#### 方式二：手动升级

```bash
# 1. 备份当前版本
cp -r /www/mingliyuanma /www/mingliyuanma.bak.$(date +%Y%m%d)

# 2. 上传新版本源码包，解压覆盖
cd /www/mingliyuanma
unzip -o mingliyuanma-source-v4.1.0.zip

# 3. 保留 .env 配置（不要覆盖）
# 如果 .env 被覆盖，从备份恢复
cp /www/mingliyuanma.bak.$(date +%Y%m%d)/.env .env

# 4. 安装新依赖
npm install

# 5. 执行数据库迁移（如有新的迁移脚本）
mysql -u mingli -p mingli_db < scripts/mysql-migrate-v4.1.0.sql

# 6. 重新构建
npm run build

# 7. 复制静态资源
cp -r public .next/standalone/public
cp -r .next/static .next/standalone/.next/static

# 8. 重启服务
pm2 restart ming8

# 9. 验证
curl -I http://localhost:3001
```

### 6.5 数据库迁移

每个版本如果涉及数据库结构变更，会附带迁移脚本：

```
scripts/
├── mysql-init.sql              # 初始建表（v4.0.0）
├── mysql-migrate-v4.1.0.sql    # v4.0.0 → v4.1.0 迁移
├── mysql-migrate-v4.2.0.sql    # v4.1.0 → v4.2.0 迁移
└── ...
```

迁移脚本特点：
- 全部使用 `IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`，可安全重复执行
- 不会删除已有数据
- 每个脚本头部注明适用的版本范围

### 6.6 版本号规则

采用语义化版本号：`主版本.次版本.修订号`

| 版本变化 | 含义 | 示例 |
|------|------|------|
| `主版本` (X.0.0) | 架构大改，可能需要手动适配 | v4.0.0 → v5.0.0 |
| `次版本` (X.Y.0) | 新增功能，向下兼容 | v4.0.0 → v4.1.0 |
| `修订号` (X.Y.Z) | Bug 修复，完全兼容 | v4.0.0 → v4.0.1 |

### 6.7 回滚方案

如果升级后出现问题，可快速回滚：

```bash
# 一键回滚
cd /www
mv mingliyuanma mingliyuanma.failed
cp -r mingliyuanma.bak.YYYYMMDD mingliyuanma
cd mingliyuanma
pm2 restart ming8
```

## 八、常见问题

### Q1：升级会丢失数据吗？
**不会。** 升级脚本只更新代码和数据库表结构，不会动用户数据。但建议升级前手动备份数据库：
```bash
mysqldump -u mingli -p mingli_db > backup-$(date +%Y%m%d).sql
```

### Q2：升级后网站打不开怎么办？
执行回滚：
```bash
cd /www
mv mingliyuanma mingliyuanma.failed
cp -r mingliyuanma.bak.YYYYMMDD mingliyuanma
cd mingliyuanma && pm2 restart ming8
```

### Q3：可以跳版本升级吗？
可以。比如从 v4.0.0 直接升级到 v4.3.0，只需执行中间所有版本的迁移脚本：
```bash
mysql -u mingli -p mingli_db < scripts/mysql-migrate-v4.1.0.sql
mysql -u mingli -p mingli_db < scripts/mysql-migrate-v4.2.0.sql
mysql -u mingli -p mingli_db < scripts/mysql-migrate-v4.3.0.sql
```

### Q4：如何查看当前版本号？
登录管理后台，左下角显示版本号。或查看：
```bash
cat /www/mingliyuanma/package.json | grep version
```

### Q5：可以自己修改代码吗？
可以。源码买断版授权您完全自定义二次开发。但注意：
- 修改后的代码不影响授权码验证
- 如果修改了数据库结构，升级时需手动合并
- 建议修改前做好备份

### Q6：授权码换域名怎么办？
联系客服，提供原授权码和新域名，我们会重新生成绑定新域名的授权码（免费 1 次，之后 ¥100/次）。
