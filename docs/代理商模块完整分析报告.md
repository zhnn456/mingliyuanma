### 1.2 闭环分析结论

**当前未形成完整闭环。** 主要断裂点：

```
代理商创建 → 资质审核 → 授权码发放 → 代理商推广 → 订单产生 → 分润计算 → 分润记录 → 结算申请 → 管理审批 → 打款
                                                                                      ↑              ↑
                                                                                  ❌ 表名不一致    ❌ 逻辑断裂
```

**三处断裂：**
1. **分润记录查询失败** — LIMIT参数绑定导致API返回500
2. **结算表三表分裂** — Settlement / SettlementRecord / AgentSettlement 各自独立
3. **审批不联动** — 管理后台审批不更新分润记录状态和代理商余额

## 二、严重BUG清单（必须修复）

### 🔴 BUG-1：LIMIT/OFFSET 参数绑定错误

**影响范围：** 所有分页查询API返回500错误

**问题文件和行号：**

| 文件 | 行号 | 问题SQL |
|------|------|---------|
| `src/app/api/admin/agent-review/route.ts` | 44 | `LIMIT ? OFFSET ?` 参数绑定 |
| `src/app/api/admin/commissions/route.ts` | 33 | `LIMIT ? OFFSET ?` 参数绑定 |
| `src/lib/commission.ts` | 332 | `listCommissionRecords` 中 `LIMIT ? OFFSET ?` |
| `src/lib/commission.ts` | 363 | `listSettlements` 中 `LIMIT ? OFFSET ?` |
| `src/app/api/admin/agent-settlement/route.ts` | 85 | `LIMIT ? OFFSET ?` 参数绑定 |

**原因：** MySQL prepared statements 不支持 LIMIT/OFFSET 参数绑定

**修复方案：** 将 LIMIT/OFFSET 直接拼接为数字（已验证安全，因为值来自 parseInt）

```typescript
// 修复前
sql += ' ORDER BY createdAt DESC LIMIT ? OFFSET ?';
params.push(pageSize, offset);
const rows = await queryAll(sql, ...params);

// 修复后
sql += ` ORDER BY createdAt DESC LIMIT ${pageSize} OFFSET ${offset}`;
const rows = await queryAll(sql, ...params); // params中不再包含LIMIT参数
```

### 🔴 BUG-2：commission.ts 双引号字符串被错误转换

| 216 | `status = "pending"` | `status = 'pending'` |

### 🔴 BUG-3：三张结算表数据不互通

**影响范围：** 代理商申请结算后，管理后台看不到；管理后台审批后，代理商看不到结果

**问题：** 系统中存在三张不同的"结算"表：

| 表名 | 使用位置 | 用途 |
|------|---------|------|
| `Settlement` | `agent/settlements/route.ts`、`admin/settlements/route.ts` | 代理商申请结算、管理后台审批 |
| `SettlementRecord` | `commission.ts`、`agent/agent-settlements/route.ts` | 周结算单生成、提现申请 |
| `AgentSettlement` | `admin/agent-settlement/route.ts` | 管理后台手动创建结算 |

**修复方案：** 统一使用一张表 `SettlementRecord`，废弃其他两张表。所有结算操作都读写同一张表。

### 🔴 BUG-4：PRAGMA table_info 结果访问错误

**问题文件：** `src/app/api/admin/settlements/route.ts` 第25行

```typescript
// 问题代码
const cols = await queryAll("PRAGMA table_info('Settlement')") as any[];
const colNames = cols.map(c => c.name); // ❌ SHOW COLUMNS 返回 Field 而非 name
```

**修复方案：**
```typescript
const cols = await queryAll("SHOW COLUMNS FROM `Settlement`") as any[];
const colNames = cols.map(c => c.Field);
```

### 🔴 BUG-5：建表语句使用 SQLite 语法

**问题文件：** `src/app/api/admin/agent-settlement/route.ts` 第6-18行

```sql
-- 问题代码
createdAt TEXT DEFAULT (datetime('now'))

-- 经过 adaptSql 转换后变成
createdAt TEXT DEFAULT (NOW())
-- MySQL 不允许 TEXT 类型设置 DEFAULT 表达式
```

**修复方案：** 使用 MySQL 标准语法
```sql
CREATE TABLE IF NOT EXISTS AgentSettlement (
  id VARCHAR(255) NOT NULL PRIMARY KEY,
  agentId VARCHAR(255) NOT NULL,
  period VARCHAR(20) NOT NULL,
  totalAmount DOUBLE DEFAULT 0,
  commissionRate VARCHAR(20),
  commissionAmount DOUBLE DEFAULT 0,
  status VARCHAR(50) DEFAULT 'pending',
  paidAt DATETIME,
  remark TEXT,
  createdAt DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updatedAt DATETIME
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
```

## 四、代理商运营规则

### 4.1 代理商等级体系

| 等级 | 月度GMV要求 | 基础分润比例 | 阶梯加成 | 权益 |
|------|------------|-------------|---------|------|
| Bronze（青铜） | 0-5,000 | 50% | 0% | 基础功能 |
| Silver（白银） | 5,001-20,000 | 50% | +3% | 自定义品牌、子域名 |
| Gold（黄金） | 20,001-50,000 | 50% | +5% | 自定义定价、白标 |
| Platinum（铂金） | 50,001+ | 50% | +8% | 专属客服、优先结算 |

**升降级规则：**
- 每月1日根据上月GMV自动调整等级
- 连续3个月未达到当前等级标准，自动降级
- 升级立即生效，降级有7天缓冲期

### 4.2 分润计算规则

```
分润基数 = 订单实付金额 - 支付手续费(1%) - 优惠券金额
分润金额 = 分润基数 × (基础比例 + 阶梯加成)
新客加成 = min(500, 分润基数 × 新客加成比例)  // 仅首单
总佣金 = 分润金额 + 新客加成
```

**规则说明：**
- 基础比例默认50%（会员/供奉），PDF报告默认60%
- 阶梯加成取 `max(代理商等级加成, 规则配置加成)`
- 新客加成仅限该代理商首次下单的客户，上限500元
- 退款订单自动冲销分润，不区分部分退款/全额退款

### 4.3 结算规则

| 规则 | 说明 |
|------|------|
| 结算周期 | 月结（每月1日生成上月结算单） |
| 最低提现 | ¥100 |
| 提现申请 | 代理商可随时申请提现，审核后打款 |
| 打款时效 | 审核通过后3个工作日内打款 |
| 打款方式 | 银行卡/支付宝/微信 |
| 结算状态 | pending → approved → paid / pending → rejected |

### 4.4 授权码规则

| 规则 | 说明 |
|------|------|
| 授权码格式 | HMAC-SHA256签名，不可伪造 |
| 有效期 | 默认365天，可续费延长 |
| 授权功能 | bazi, ziwei, qimen, meihua（默认全开） |
| 最大用户数 | 默认1000，可按等级调整 |
| 域名绑定 | 可选，绑定后仅限该域名使用 |
| 重新生成 | 旧码立即失效，新码即时生效 |

### 4.5 代理商行为规范

1. **禁止刷单**：检测到异常订单（同IP高频、金额异常）将冻结分润并审核
2. **禁止虚假宣传**：代理商不得虚假承诺算命效果，违者暂停授权
3. **客户数据保护**：代理商仅可查看自己名下客户数据，不得跨代理商查询
4. **分润冻结**：收到客户投诉或退款纠纷时，相关分润暂时冻结
5. **授权码保密**：授权码仅限代理商本人使用，不得转让或共享

### 4.6 资质审核规则

1. **必备资料**：联系人姓名、联系电话、登录邮箱
2. **可选资料**：公司名称、品牌名称、自定义域名
3. **审核时效**：提交后24小时内完成审核
4. **拒绝后处理**：代理商可修改资料后重新提交
5. **暂停处理**：审核通过后违规可暂停授权，暂停后可申诉恢复
